## 目的

Media Agent 要件定義書 v0.2 の **Stage 0（Media Agent Core）** を実装可能な状態にする。
このタスクは Stage 0 全体の骨格を決める。ここが決まらないと T-002 以降が一切動けない。

要件定義書24節「未決事項」と28節「最初に決定する対象」は、要件定義書自身が
「要件定義後の基本設計・詳細設計フェーズで決定する」としている。**その決定を行うのがこのタスクである。**

決めなかった項目は、下流の実装エージェントが推測で埋めることになる。**推測は必ず食い違う。**

## 変更範囲

- `docs/design/` 配下に設計成果物を新規作成する（ディレクトリごと新設してよい）
- 本ファイル `docs/tasks/T-001.md` の 決定ログ / 作業ログ / 証拠 / 進捗

## 禁止事項

- **コードを書かない。** このタスクの成果物は設計文書だけである
- `docs/requirements-media-agent-v0.2.md` を書き換えない（要件定義書は PO の持ち物）
- `docs/task-list-media-agent.csv` / `docs/handover.md` / `docs/po-queue.md` を書き換えない（オーケストレーターの持ち物）
- 他のタスクの `docs/tasks/T-XXX.md` を書き換えない
- **Stage 1 以降の設計をしない。** Content / Research / Strategy / Analytics / Engagement / Orchestrator の
  各 Agent、X Connector、Google News、RSS、Web の設計は今回の範囲外。
  ただし「将来それらを追加できる拡張点をどこに置くか」は Stage 0 の責務なので、拡張点の位置だけは決める
- **X API の利用方式・AI 処理の実行方式・Memory/Similarity 検索方式・Package 配布方式・Agent Plugin API を決めない**
  （要件定義書24節のうち Stage 0 の範囲外の項目。決めても実装されないまま陳腐化する）

## 判断してよい範囲

**技術選定は全てあなたが決めてよい。** PO へは上げない。要件定義書自身が設計フェーズでの決定としており、
技術的優劣で決着がつくため。ただし**却下案と却下理由を必ず残すこと**。

以下も自律的に決めてよい。

- 設計文書のファイル分割・章立て（`docs/design/` 配下であれば自由）
- ディレクトリ名・モジュール名・クラス名の命名
- 要件定義書の記述に幅がある箇所を、Stage 0 の範囲で最小に解釈すること
- Stage 0 で `setup` / `task` / `agent` コマンドを実装するかどうか
