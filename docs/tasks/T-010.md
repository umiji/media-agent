## 目的

Stage 0 の成果物を、**PO と外部の利用者が実際に動かせる**状態にする。
ゴール達成条件 A-6「PO 確認用の実行手順書が成果物にある」を満たすのがこのタスクである。

PO は 2026-08-23 に「PO 確認用の手順書だけ用意して先へ進む」と判断した。
**したがってこの手順書は、PO が後から一人で Stage 0 を検証するための唯一の入口になる。**
手順書に書かれていないことは、PO には伝わらない。

- `README.md`（リポジトリルート。無ければ新規作成）

- 製品コード・テストコードを書き換えない
- `docs/requirements-media-agent-v0.2.md` / `docs/task-list-media-agent.csv` / `docs/handover.md` /
  `docs/po-queue.md` / 他タスクの `docs/tasks/T-XXX.md` を書き換えない
- `CLAUDE.md` / `.claude/` 配下を書き換えない（層2はオーケストレーターの持ち物）
- **動かないコマンドを書かない。** 書いたコマンドは全て自分で実行して確認すること
- **Stage 1 以降の機能を「できる」と書かない。** 投稿・情報収集・AI 生成は Stage 0 では動作しない

## 完了条件

1. `README.md` に次がある
   - Media Agent が何であるか（要件定義書1.2節の要約）
   - **現在の実装状況が Stage 0 であること**と、Stage 0 で動くもの／動かないものの区別
   - インストール手順
   - 基本的な使い方（`init` / `doctor` / `status` / `run`）
   - 開発者向け: テストの実行方法、リントの実行方法
2. **PO 確認用の実行手順書がある。** 次を満たすこと
   - 前提（必要な Python バージョン、リポジトリの取得方法）から書かれている
   - **コピーして順に実行できるコマンド列**になっている
   - 各コマンドの**期待される出力と終了コード**が書かれている
   - 要件定義書18節 Stage 0 の検証条件（`init` → Project生成 → `doctor` → `status`）を必ず含む
   - 期待どおりにならなかった場合、どこへ報告すればよいかが書かれている
3. **手順書に書いた全コマンドを実際に実行し、記載どおりに動くことを確認している。**
   実行結果を `## 証拠` へ記録すること
4. **認証情報が不要であることが明記されている。** Stage 0 は外部サービスへ接続しないため
5. 記述が実装と食い違っている箇所を見つけた場合、**文書側で辻褄を合わせず**、報告に含める
