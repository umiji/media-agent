#### 既存の受け入れテスト2件の期待値を、あなたが更新すること（重要）

**D-2（`Agent.version` の永続化）により `AUDIT_SCHEMA_VERSION` が 1 → 2、Migration 版数が 1 → 2 になる。**
そのため既存の受け入れテスト2件のリテラルが古くなる。

- `tests/acceptance/test_stage0_audit.py:64` — `record["schema_version"] == 1`
- `tests/acceptance/test_stage0_lifecycle_sequence.py:104` — `payload["database"]["schema_version"] == 1`

**これは「落ちているテストを通すための書き換え」ではなく、設計変更に伴う期待値の更新である。**
**更新する主体はあなた（org-test）であり、T-014（実装）は禁じられている。** 本タスクで直しておくこと。
`tests/acceptance/test_stage0_status.py:68` は定数比較のため修正不要（T-012 が確認済み）。

**この2件だけが対象である。** 他のテストの期待値には触れないこと。

## 禁止事項

- **製品コード（`src/` 配下）を変更しない**
- **設計成果物（`docs/design/` 配下）を書き換えない。** T-012 の期待値に疑義があれば、
  直さずに停止条件として報告する（org-design へは1往復まで問い合わせてよい）
- **T-012 が定めていない期待値を自分で作らない。** 決まっていないものがあれば報告する。
  **これが T-003 で起きた「独自解釈が契約になる」問題の再発防止である**
- 既存のテストを書き換えない
- **ネットワークへ出るテスト・認証情報を要求するテストを書かない**（PO 制約 C-1・C-2）
- `docs/task-list-media-agent.csv` / `docs/handover.md` / `docs/po-queue.md` / 他タスクの `T-XXX.md` を書き換えない
- **`os.chdir` を使わない**（方式設計 10.3）。やむを得ない場合は `monkeypatch.chdir` を使い、逸脱を docstring に明記する
  （S-J に前例がある。T-009 が妥当と判定済み）
