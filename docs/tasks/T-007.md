### 2026-08-24 `doctor` の DB 検査は読み取り専用の接続で行う

- 理由: `PolicyEngine` は上限判定のために `decisions` を数えるため接続が要る。一方 `doctor` は
  プロジェクトの DB を作らない・触らない。**この検査が見るのは設定の妥当性であり実行回数ではない**ため、
  空の DB で判定して差し支えない
- 却下案: プロジェクトの DB を開いて渡す → DB が無い場合に検査14 が道連れで `skipped` になり、
  「設定が正しいか」を DB の有無に依存させることになる
- 出典: 詳細設計 13.2 の検査14 / 罠 D-T14 / 申し送り M-5、コミット `2f12cbd`

### 2026-08-24 設定が壊れているときの検査4・5の扱い

  `config.version` が `fail`（未対応版数）なら `config.schema` は `skipped`
- 理由: 詳細設計 13.4 は「壊れている設定では 3・4・5 のいずれかが `fail` になり、依存する検査は

- 却下案: 評価できない検査も `fail` にする → 1つの原因（YAML の構文崩れ）が3件の不合格として数えられ、
  「何件直せばよいか」が読めなくなる

### 2026-08-24 `-q/--quiet` は結果そのものの出力を抑制しない
