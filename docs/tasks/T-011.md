## 目的

受け入れテストが SQLite の接続を閉じずに捨てているため、**Python 3.13 で `ResourceWarning: unclosed database`
が 22 件出る**。テストは通るため見逃されやすいが、これは**組織自身のテスト資産の欠陥**である。

放置すると、Stage 1 以降でテストが増えたときに警告が埋もれ、**本物のリークが出ても気づけなくなる。**
警告が「常に出ているもの」になった時点で、警告としての機能を失う。

## 変更範囲

- `tests/acceptance/expectations.py` の `build_policy_engine`（T-008 が確保箇所を特定済み。13/13 件がここ）
- 同じ問題が他の受け入れテストにあれば、そこも
- 本ファイル `docs/tasks/T-011.md` の 決定ログ / 作業ログ / 証拠 / 進捗

## 禁止事項

- **製品コード（`src/` 配下）を変更しない。** これはテスト側の欠陥である
  （T-008 が確認済み: `ResourceWarning` を error へ昇格させて CLI だけを走らせると警告 0 件）
- **テストの期待値を変えない。** 接続の後始末を足すだけであり、判定内容は変わらないはず
- 設計成果物（`docs/design/` 配下）を書き換えない
- `docs/task-list-media-agent.csv` / `docs/handover.md` / `docs/po-queue.md` / 他タスクの `T-XXX.md` を書き換えない
- スコープ外のリファクタリングをしない
