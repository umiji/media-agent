## 決定ログ

### 2026-08-25 `db_path` がディレクトリの場合の検査を、独立した関数として足した

- 決定: 詳細設計 4.1 の `verify_project_structure(layout, *, paths)` は**シグネチャどおり**に実装し、
  12.5 が preflight の検査対象に挙げる「`data/media-agent.db` がディレクトリでないこと」は
  別の関数 `verify_not_a_directory(path)` として足した
- 却下案: `verify_project_structure` に `files=` の省略可能な引数を足す → **設計が明示したシグネチャを変えることになる。**
  検査の向きが逆（ファイルであるべき／ディレクトリであるべき）であり、同じ引数名で両方を受けると読み手が向きを取り違える
- 却下案: `db_path` の検査を省き、`sqlite3` の `OSError` に任せる → 12.5 が preflight の検査対象として明示しており、
  preflight を通り抜けると生成物を書いてから落ちる（R-5 違反）
- 出典: 詳細設計 4.1 / 12.5 / 17.4.1。実装は `src/media_agent/project/layout.py`

### 2026-08-25 `db_path` がディレクトリのときのメッセージは「通常のファイルではありません」にした

- 決定: 17.4.3 が規範とする `ProjectStructureError` の文面は「{絶対パス} はディレクトリではありません」だが、
  **この1ケースだけは向きが逆**であるため「{絶対パス} は通常のファイルではありません」とし、`details` に
  「ディレクトリになっています」を添えた。Hint は共通（`退避` + `media-agent init`）
- 却下案: 17.4.3 の文面をそのまま使う → 対象は現にディレクトリであり、「ディレクトリではありません」は事実に反する。
  利用者が読んで意味が反転する
- 付帯条件: **受け入れテストはこのケースを判定していない**（S-D2 の壊し方3種に含まれない）。
  17.3 の安定文字列表にも該当行が無いため、表の外側であり実装の裁量に収まると判断した
- 出典: 詳細設計 17.3 / 17.4.3。実装は `src/media_agent/project/layout.py` の `verify_not_a_directory`

### 2026-08-25 `_ensure_base_dir` の hint を復旧手順（`QUARANTINE_HINT`）へ揃えた

- 決定: `.media-agent/` 自体が通常ファイルのときの `ScaffoldError` の hint を
  「このパスにあるファイルを退避してから、**もう一度実行してください**」から
  「…退避してから **media-agent init を実行してください**」へ変えた
- 却下案: 従来の文面のままにする → 意味は同じだが、**構造破損の Hint とだけ文面が違う**状態が残る。
  R-6 が求めるのは「助言と結果が一致すること」であり、コマンド名を明示する方が行き止まりを作らない
- 付帯条件: **終了コード（1）と例外型（`ScaffoldError`）は変えていない**（12.5 で確定済みの判断を蒸し返さない）
- 出典: 詳細設計 12.5 / 17.4.3

### 2026-08-25 `record_agent_run` の `agent_version` を必須の引数にした

- 決定: 詳細設計 11.3 のシグネチャどおり `agent_version: int` を**既定値なしの必須**にした。
  既存の単体テスト10件の呼び出しを追随させた
- 却下案: `agent_version: int | None = None` にする → 呼び出し側が渡し忘れても通るため、
  **記録先を作ったのに値が入らない経路**ができる。RV-3（受け皿が無い）を直す意味が薄れる
- 出典: 詳細設計 11.3。実装は `src/media_agent/core/observability/audit.py`
