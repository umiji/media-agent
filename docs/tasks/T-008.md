## 目的

Stage 0 が**仕様の側から見て**完成しているかを判定する。実装エージェントの自己申告ではなく、
独立した実行と観測によって、ゴール達成条件 A-2 と A-4 の充足を確定させる。

要件定義書25節は「各Stageは、実装完了ではなく実運用上の検証完了をもって完了とする」としている。
**このタスクがその検証にあたる。**

## 変更範囲

- 受け入れテストの実行と、結果の記録
- 不足しているシナリオテスト・回帰テストの**追加**（T-003 で書いたものに足りない観点があれば）
- 本ファイル `docs/tasks/T-008.md` の 決定ログ / 作業ログ / 証拠 / 進捗

## 禁止事項

- **製品コードを修正しない。** 不具合を見つけたら org-implementation へ不具合レポートを返す（2往復まで）。
  2往復で解決しなければ、解決していなくてもオーケストレーターへ返す
- **テストの期待値を実装に合わせて書き換えない。** 期待値が誤っていると判断したら、
  設計成果物と突き合わせたうえで報告する
- 設計成果物（`docs/design/` 配下）を書き換えない
- `docs/task-list-media-agent.csv` / `docs/handover.md` / `docs/po-queue.md` / 他タスクの `T-XXX.md` を書き換えない
- 単体テストを書かない（実装エージェントの担当）
- **ネットワークへ出るテスト・認証情報を要求するテストを書かない**（PO 制約 C-1・C-2）

## 完了条件

1. **受け入れテスト S-A 〜 S-I を実行し、全通過している。** 実行コマンドと実出力を `## 証拠` へ記録する
2. **実環境で、要件定義書18節 Stage 0 の検証条件を人手で再現している。**
   一時ディレクトリで `media-agent init` → `media-agent doctor` → `media-agent status` を実際に実行し、
   **各コマンドの実出力と終了コードを `## 証拠` へ貼る**。ゴール達成条件 A-2 の根拠となる
3. 単体テストを含む**全テストが通っている**（実行コマンドと実出力を記録）
4. 次のシナリオテストが存在し、通っている（T-003 に無ければ追加する）
   - **S-J** 別々の2ディレクトリで `init` したとき、DB・ログ・Memory が**互いに混ざらない**
     （要件定義書5.4節「Memoryは他プロジェクトと完全分離する」）
   - **S-K** 同じディレクトリで `init` → `doctor` → `status` → `run` → `status` と続けて実行しても壊れない
5. **Stage 1 以降の機能が実装されていないことを確認している**（ゴール達成条件 A-8）。
   具体的には、リポジトリ内に X API クライアント・外部 HTTP 送信・LLM 呼び出しのコードが**無い**ことを
   検索で確認し、確認に使ったコマンドと結果を `## 証拠` へ記録する
6. 不具合を検出した場合、**再現手順・原因の切り分け・該当箇所**を添えて org-implementation へ返し、
   その往復の結果が `## 作業ログ` に記録されている
