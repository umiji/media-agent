## 目的

Media Agent を「Python パッケージとして import でき、CLI として起動でき、任意のプロジェクトへ導入できる」
状態にする。要件定義書 Stage 0 の土台であり、T-005 以降の全実装がこの上に乗る。

要件定義書28節が Stage 0 のゴールとして挙げる
«「Media Agentという汎用基盤を、任意のプロジェクトに導入して動かせる」» の、**導入部分**がここである。

## 変更範囲

- Python パッケージ本体のうち、次の領域（具体的なパスは T-001 の方式設計に従う）
  - パッケージ骨格（`pyproject.toml` 等のパッケージ定義、バージョン管理）
  - **ruff / mypy / pytest の設定**（T-001 の差分 D-1。`pyproject.toml` 内に置く。
    全実装タスクの共通完了条件が「T-001 が定めたリントコマンドが通る」である以上、
    設定は T-004 の時点で存在していなければならない。T-007 まで待てない）
  - CLI エントリポイントとコマンド登録の仕組み
  - Config の読み込み・スキーマ検証
  - `media-agent init`（`.media-agent/` の生成）
- `.gitignore`（要件定義書14.2節。Credential をコミットしないための設定）
- 上記に対応する単体テスト
- 本ファイル `docs/tasks/T-004.md` の 決定ログ / 作業ログ / 証拠 / 進捗

**DB・Logging/Audit（T-005）、Agent Runtime・Task・Policy（T-006）、doctor/status/run の中身（T-007）は
このタスクの範囲外。** CLI にコマンドを登録する枠だけ用意し、中身は次タスクへ渡してよい。

## 完了条件

1. パッケージが T-001 の定めた方式でインストールでき、**`media-agent --help` が動作する**
2. **要件定義書10節の10コマンドが CLI に登録されている。**
   T-001 が定めた切り分けに従い、Stage 0 で実装しないコマンド（`post` / `research` / `analyze` など）は
   「未実装である」と明示するメッセージを出して終了すること。**沈黙して成功しないこと**
3. `media-agent init` が、要件定義書8.1節の `.media-agent/` 構造を生成する
   （`config.yaml` / `strategy.md` / `rules.md` / `agents/` / `memory/` / `data/` / `logs/`）。
   生成物の中身は T-002 の詳細設計に従う
4. 既に `.media-agent/` が存在する場合の挙動が、T-002 の設計どおりに実装されている。
   **`init --force` を含む**（T-002 の範囲追記。詳細設計 12.5。完了条件4 の対象内であり、境界の変更ではない）
5. Config の読み込みとスキーマ検証が実装され、**壊れた `config.yaml` / 必須項目の欠落に対して
   設計どおりのエラーで落ちる**（受け入れテスト S-I）
6. `init` していないディレクトリでコマンドを実行したとき、**明確なエラーメッセージと非ゼロ終了コード**になる
   （受け入れテスト S-D。ただし `init` 自身と `--help` を除く）
7. **受け入れテスト S-A / S-D / S-I が通る**
8. `.gitignore` により、Credential ファイル（`.env` 等）がコミット対象から除外されている

## 禁止事項

- **受け入れテスト（T-003 が書いたテスト）を書き換えて通さない。** テストが誤っていると判断したら、
  直さずに停止条件として報告する。`.claude/rules/org-task-ledger.md`「やってはいけないこと」に該当する
- 設計成果物（`docs/design/` 配下）を書き換えない。読み方に迷ったら org-design へ問い合わせる（1往復まで）
- `docs/requirements-media-agent-v0.2.md` / `docs/task-list-media-agent.csv` / `docs/handover.md` /
  `docs/po-queue.md` / 他タスクの `docs/tasks/T-XXX.md` を書き換えない
- **X API クライアントを書かない。外部ネットワークへ送信するコードを書かない**（PO 制約 C-1・C-3、
  および要件定義書28節「Stage 0ではまだX APIやニュース取得等を実装しない」）
- **認証情報を必要とする実装をしない。** 認証情報をリポジトリへ置かない（PO 制約 C-2、要件定義書14.2節）
- **Stage 1 以降の機能を実装しない。** Content / Research / Strategy / Analytics / Engagement / Orchestrator の
  各 Agent、Google News / RSS / Web Connector、過去投稿 Import、重複チェック、AI 呼び出しは範囲外
- **本タスクの `変更範囲` の外にあるファイルを変更しない。** 他の実装タスクが担当する領域に不足を見つけても、
  その場で直さずに報告する（`CLAUDE.md`「スコープを勝手に広げない」）
- スコープ外のリファクタリング・警告修正をしない
