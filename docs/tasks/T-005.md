## 目的

Agent の判断・実行・結果を**記録できる状態**を作る。要件定義書の開発原則7
「過去の判断・Action・結果を可能な限り記録する」と、非機能要件20.3（可観測性）・20.5（再現性）の土台である。

Logging / Audit は T-006 の Agent Runtime が使う。**先に無いと、Runtime は記録なしで動いてしまう。**

## 変更範囲

- DB 層（要件定義書16節の6 Entity: Project / Source / Post / Performance / Task / Decision）
  - スキーマ定義、初期化、Migration の仕組み
  - 各 Entity の作成・取得・更新（Stage 0 で必要な範囲）
- Logger（運用ログ）
- Audit（判断の追跡記録。要件定義書5.5節の9項目）
- 上記に対応する単体テスト
- 本ファイル `docs/tasks/T-005.md` の 決定ログ / 作業ログ / 証拠 / 進捗

**Agent Runtime / Task の状態遷移ロジック / Policy Engine は T-006 の範囲。**
このタスクは Task Entity の**永続化**までを担当し、状態遷移の制御は T-006 が実装する。

## 完了条件

1. T-002 の DB Schema どおりに6 Entity のテーブルが作成される

- `docs/requirements-media-agent-v0.2.md` / `docs/task-list-media-agent.csv` / `docs/handover.md` /
  `docs/po-queue.md` / 他タスクの `docs/tasks/T-XXX.md` を書き換えない
- **X API クライアントを書かない。外部ネットワークへ送信するコードを書かない**（PO 制約 C-1・C-3、
  および要件定義書28節「Stage 0ではまだX APIやニュース取得等を実装しない」）
- **認証情報を必要とする実装をしない。** 認証情報をリポジトリへ置かない（PO 制約 C-2、要件定義書14.2節）
- **Stage 1 以降の機能を実装しない。** Content / Research / Strategy / Analytics / Engagement / Orchestrator の
  各 Agent、Google News / RSS / Web Connector、過去投稿 Import、重複チェック、AI 呼び出しは範囲外
- **本タスクの `変更範囲` の外にあるファイルを変更しない。** 他の実装タスクが担当する領域に不足を見つけても、
  その場で直さずに報告する（`CLAUDE.md`「スコープを勝手に広げない」）
- スコープ外のリファクタリング・警告修正をしない
- **既存データを削除する処理・破壊的な Migration を書かない。** 必要になったら停止条件（共通 S-2）
