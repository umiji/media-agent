## 目的

Agent の判断・実行・結果を**記録できる状態**を作る。要件定義書の開発原則7
「過去の判断・Action・結果を可能な限り記録する」と、非機能要件20.3（可観測性）・20.5（再現性）の土台である。

Logging / Audit は T-006 の Agent Runtime が使う。**先に無いと、Runtime は記録なしで動いてしまう。**

## 変更範囲

- DB 層（要件定義書16節の6 Entity: Project / Source / Post / Performance / Task / Decision）
  - スキーマ定義、初期化、Migration の仕組み

- Logger（運用ログ）
- Audit（判断の追跡記録。要件定義書5.5節の9項目）
- 上記に対応する単体テスト
- 本ファイル `docs/tasks/T-005.md` の 決定ログ / 作業ログ / 証拠 / 進捗

**Agent Runtime / Task の状態遷移ロジック / Policy Engine は T-006 の範囲。**
このタスクは Task Entity の**永続化**までを担当し、状態遷移の制御は T-006 が実装する。
